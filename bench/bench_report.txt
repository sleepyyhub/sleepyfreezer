============================== READING THIS =============================
"notify remote 0.0 ns (0/4000 sent)" on the original is not a timing.
FireDirect calls only the FIRST enabled handler, so it measures who runs
first. On the original our handler was never first: pole is taken once at
boost and silently lost on the next rebind. In a real client every handler
still runs, so the original would not miss the code -- it would send it
after the game's handler had finished. That is the cost, and it is the
same defect either way.

"3700/4000" on the original's label surface is 300 announcements that
produced no send at all.

CAVEATS
  - Container CPU, not the M3 Air. The ratios carry over, the absolutes
    do not.
  - InvokeServer here is a Lua stub (~48 ns). The real one is a C call
    that serialises and queues a packet, so the real redeem costs more
    than any detection figure above -- which is the point: detection is
    no longer the slower half on any surface.
  - The label figures exclude the harness's own property-signal cost, so
    they are LUCK's contribution only.
  - Lua work only. Says nothing about the wire or the network send step.
